# Статус реализации MVP

## Текущий результат

Реализовано ядро сценария «план между поступлениями»:

- чистый старт без демонстрационных и личных сумм;
- отдельный ввод текущего доступного остатка, не являющийся доходом;
- ввод фактического поступления и даты следующего поступления;
- конверты для обязательных платежей, подушки, долга и расходов на жизнь;
- раскрывающийся экран «План» с добавлением обязательного платежа, долгового обязательства или расхода из соответствующего блока;
- раздельная проверка покрытия обычных обязательств и долга;
- факт расхода или оплаченного обязательства уменьшает счёт и соответствующий конверт ровно один раз.

## Проверено

- `pnpm test`: 19 тестов финансовой логики проходят.
- `pnpm build`: production-сборка проходит.
- Проверены сценарии: ожидаемый доход не становится доступным раньше времени; плановые расходы не учитываются дважды; распределение сверх доступного остатка не получает статус «в плане»; долг проверяется против конверта «Долг».

## Следующий безопасный этап

Провести пользовательскую проверку порядка и формулировок в сценарии: текущий остаток → следующее поступление → распределение → добавление коммунальных/связи/долга → расход на жизнь → отметка оплаты. После обратной связи исправлять только подтверждённые точки непонимания, не расширяя MVP сторонними финансовыми разделами.

## Важно для следующего агента

Перед изменением прочитайте `MVP_DECISIONS.md`, этот файл и раздел 0 в `SPECIFICATION.md`. Не возвращайте раздел «Ещё» как хранилище финансовых сущностей: обязательства, долг и расходы на жизнь принадлежат раскрывающемуся экрану «План».
